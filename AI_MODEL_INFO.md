# AI Model & Report Generation Audit

**Document Date:** September 2026  
**Project:** Explainable AI Diabetes Prediction System  
**Audit Target:** `services/ai_report.py`, environment configurations, and Streamlit report workflow  

---

## 1. Core Summary Specifications

- **LLM Provider:** Configured to `openai` (primary) with support for `gemini`
- **Model:** `gpt-4o-mini` (OpenAI) / `gemini-1.5-flash` (Google Gemini)
- **API:** Direct HTTPS REST API (`https://api.openai.com/v1/chat/completions` or `https://generativelanguage.googleapis.com/v1beta/models/...`)
- **Environment Variable:** `LLM_API_KEY` (along with `LLM_PROVIDER` and `LLM_MODEL`)
- **Current Status:** **Template-Based Fallback Mode** (No API key is currently supplied in `.env`)
- **Fallback Mechanism:** Deterministic 12-section structured clinical template engine executed locally with zero network dependencies

---

## 2. Explicit Audit Responses

### 1. Which LLM/provider is currently being used?
- **Finding:** In `services/ai_report.py`, the system is configured to read `LLM_PROVIDER` from `.env` (defaulting to `openai`). If set to `openai`, it targets OpenAI Chat Completions; if set to `gemini`, it targets Google Generative Language API.
- **Current Reality:** Because no active API key has been populated into `.env`, **no external LLM provider is currently receiving API calls**.

### 2. Which exact model name is being used?
- **Finding:** The model is read from `os.getenv("LLM_MODEL")`.
  - For OpenAI: `gpt-4o-mini` (or `gpt-4o`).
  - For Gemini: `gemini-1.5-flash` (or `gemini-2.0-flash`).
- **Current Reality:** Without an API key, the model name is only a configuration setting and is not actively being invoked over the wire.

### 3. Is the report actually generated by an LLM?
- **Finding:** **No.** Under the current project configuration, the report is **NOT** generated by an LLM.
- **Proof:** In `services/ai_report.py`, line 196 explicitly checks:
  ```python
  if not api_key:
      return generate_fallback_report(...)
  ```
  Since `LLM_API_KEY` in `.env` is blank, this branch triggers 100% of the time.

### 4. Is it currently just a template-based report?
- **Finding:** **Yes.** It is currently 100% a deterministic, rule-based template report produced by `generate_fallback_report()` using string interpolation of patient measurements, probability thresholds, and calculated SHAP values.

### 5. Where is the API key configured?
- **Finding:** The API key is configured in the root `.env` file at the project root:
  `d:\Downloads\Explainable-AI-Diabetes - Copy\.env`
- A reference template is also maintained in `.env.example`.

### 6. Which environment variable is expected for the API key?
- **Finding:** `LLM_API_KEY`.
- Additional related environment variables:
  - `LLM_PROVIDER`: `openai` or `gemini`
  - `LLM_MODEL`: `gpt-4o-mini` or `gemini-1.5-flash`

### 7. What happens when the API key is missing?
- **Finding:** The application does **not** crash.
  1. `generate_patient_report` detects that `api_key` is empty.
  2. It immediately routes execution to `generate_fallback_report(...)`.
  3. The returned report dictionary sets `"is_ai_generated": False` and `"provider": "Deterministic Template Engine (No external API key required)"`.
  4. The Streamlit UI displays the structured template report and clearly states that the fallback template is in use rather than claiming AI generation.
  5. Machine learning predictions, probability calculations, SHAP charts, and LIME explanations continue working completely unimpeded.

## 3. Grounding & Disclaimers

The system enforces strict medical and ethical guardrails:
- The AI report generator is prohibited from inventing clinical history, prescribing medication, or diagnosing conditions.
- The report is strictly framed as explaining the computational behavior and feature attributions of the trained machine learning model.
- The mandatory non-diagnostic disclaimer is appended to all outputs:
  > *"This report is generated by an AI system for educational/research purposes. It is not a medical diagnosis and should not replace consultation with a qualified healthcare professional."*
